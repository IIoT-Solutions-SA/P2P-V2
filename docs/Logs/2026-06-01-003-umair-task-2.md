# Umair Task 2 — Block Personal Email Changes After Login

**Date:** 2026-06-01 AST  
**Repo:** P2P-V2  
**Branch to start from:** `hamza-backend`

## Summary

KACST issue 11 is about users being able to change their account email after login from a corporate/work email to a personal email.

Signup already blocks common personal email domains, but the profile email-change flow must also enforce the same rule.

## Task

Update the logged-in email change flow so users cannot change their account email to a personal email address.

### Target behavior

- User can only change email to an allowed corporate/work email.
- Reject blocked personal domains such as Gmail, Yahoo, Hotmail, Outlook, iCloud, ProtonMail, Live, and MSN.
- If the user belongs to an organization, the new email should stay within the allowed organization/company domain.
- Current password verification should still be required before changing email.
- SuperTokens, PostgreSQL, and MongoDB email values should only be updated after validation passes.
