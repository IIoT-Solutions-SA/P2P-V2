# **Use Case Submission – IoT Kit for OEE Tracking**

---

## **1\. Basic Information Section**

**Title**  
 IoT Kit for OEE Tracking

**Subtitle**  
 IoT-driven real-time OEE tracking improves machine reliability and efficiency

**Description/Executive Summary**  
 The IoT Kit for OEE Tracking enables continuous monitoring of machine components and performance parameters. It consolidates spindle/axis status, fluid and coolant levels, and sensor conditions into a single health dashboard, empowering predictive maintenance and improving overall equipment effectiveness (OEE).

## **3\. Business Challenge**

**Industry Context**  
 Precision manufacturing requires machines to operate at peak efficiency with minimal downtime. Even small inefficiencies affect throughput and product quality. Traditional OEE tracking methods rely heavily on manual reporting, which is often delayed and lacks accuracy, limiting data-driven decision-making.

**Specific Problems**

1. Inconsistent OEE tracking due to manual data collection

2. Lack of visibility into real-time machine performance metrics

3. Increased downtime from undetected coolant or component issues

**Financial Loss/Impact**  
 Estimated SAR 937,500 annual losses from inefficiencies, downtime, and rework

---

## **4\. Solution Overview**

**Selection Criteria**

1. Ability to capture real-time machine health and OEE data

2. Easy integration with production monitoring dashboards

3. Low-latency alerts for maintenance teams

**Selected Vendor**  
 IIoT Solutions (with KACST)

**Technology Components**

* IoT sensors for spindle, axis, and coolant monitoring

* Edge modules for local processing of sensor streams

* Cloud-based OEE dashboard with predictive analytics

  ## **8\. Challenges & Solutions**

**Challenge Name**: Data Accuracy from Legacy Machines

* Description: Older machines lacked native sensor interfaces, reducing data reliability

* Solution: Installed retrofit sensor kits and developed middleware for data standardization

* Outcome: Achieved reliable data capture across 95% of machines

**Challenge Name**: Operator Adoption

* Description: Operators were initially hesitant to trust automated OEE reports

* Solution: Conducted workshops and provided mobile dashboards for transparency

* Outcome: Improved adoption and acceptance within 6 weeks

  ---

  ## **9\. Technical Architecture**

**System Overview**  
 Hybrid Edge-Cloud architecture where IoT devices capture machine data locally, process it at the edge, and stream it to a cloud-based dashboard for analytics and OEE reporting.

**Architecture Components**

* Data Layer: IoT sensors, MQTT broker

* Application Layer: Edge computing modules, middleware APIs, OEE analytics engine

* Presentation Layer: Web dashboard, mobile monitoring app

**Security Measures**

* End-to-end encryption for all data transmission

* Role-based access control (RBAC)

* Regular security audits and penetration testing

**Scalability Design**

* Modular sensor nodes for easy expansion

* Load balancing across analytics servers

* Auto-scaling cloud backend based on machine count
